# 问题排查：体验版上传图片卡住

> 2026-10-14
> 现象：三餐报备上传图片，**开发工具和真机调试正常**，**体验版卡在「压缩中，请稍后」不动**

---

## 一、结论（先说答案）

**不是代码问题，是微信后台的域名白名单没配对。**

`wx.request` 和 `wx.uploadFile` 是**两个互不相干的白名单**：

| 接口 | 查哪个白名单 | 你现在配了吗 |
|---|---|---|
| `wx.request`（所有文字接口） | **request 合法域名** | ✅ 配了 |
| `wx.uploadFile`（上传图片） | **uploadFile 合法域名** | ❌ **没配** |

之前配域名时只加了 `request 合法域名`，**上传图片走的是另一个列表**，所以：
**其他功能在体验版都正常，只有上传图片挂掉。**

---

## 二、为什么只有体验版不行？

| 环境 | 校验域名 | 上传结果 |
|---|---|---|
| 微信开发者工具 | ❌ 不校验（「不校验合法域名」开关） | ✅ 正常 |
| 真机调试 | ❌ 不校验（走调试通道） | ✅ 正常 |
| **体验版 / 正式版** | ✅ **强制校验，无任何绕过方式** | ❌ **被拦** |

> 关键：开发者工具里那个「不校验合法域名」**只对开发者工具自己生效**，
> 真机调试靠的是调试通道。**体验版是普通用户跑的，一律按正式规则校验。**

---

## 三、「压缩中，请稍后」是谁弹的？

**是微信客户端自己弹的，不是我们的代码。**

我已经全文搜索确认过：

```
grep -rn "压缩" ganluo/ server/     →  无
grep -rn "压缩" ganluo/unpackage/   →  无
```

我们代码里只有 `uni.showLoading({ title: '上传中' })`，写的是**「上传中」**。

这个「压缩中」来自 `uni.chooseImage({ sizeType: ['compressed'] })` —— 微信在压缩你选的原图时弹的原生提示。
压缩完成后才轮到我们上传，而上传那一步被域名白名单拦下了。

**所以这个提示具有误导性**：它让你以为是压缩卡住了，其实压缩早完成了，卡在上传。

---

## 四、怎么确诊（3 步，5 分钟）

### 第 1 步：打开体验版的调试模式

手机上打开体验版小程序 → 右上角 **···** → **打开调试**

屏幕右下角会出现一个绿色的 **vConsole** 按钮。

### 第 2 步：复现问题

点三餐格子 → 选图 → 等到卡住。

### 第 3 步：看 vConsole 里的报错

点开 vConsole 的 **Log** 标签，找类似这样的红字：

```
uploadFile:fail url not in domain list
```

**看到这句 → 100% 确认是域名白名单问题**，按第五节修。

> 如果看到的是别的（比如 `timeout`、`ERR_CONNECTION`），把截图发我，是另一个问题。

### 备选：直接查后台

不用复现也能确认 —— 登录 [微信公众平台](https://mp.weixin.qq.com) →
**开发管理 → 开发设置 → 服务器域名** → 看 **uploadFile 合法域名** 那一栏是不是空的。

---

## 五、修复步骤

### 1. 在微信后台补上 uploadFile 域名

微信公众平台 → **开发管理 → 开发设置 → 服务器域名**：

```
request 合法域名：    https://y.bobay.top      ← 你已配
uploadFile 合法域名：  https://y.bobay.top      ← 补这个！
```

**四个列表都要按需配**（不用的一次不用填）：

| 列表 | 用途 | 我们需要吗 |
|---|---|---|
| request 合法域名 | `wx.request` | ✅ 需要 |
| **uploadFile 合法域名** | `wx.uploadFile` 上传图片 | ✅ **需要，就是它** |
| downloadFile 合法域名 | `wx.downloadFile` | ⬜ 暂时不用 |
| socket 合法域名 | WebSocket | ⬜ 不用 |

### 2. 重新上传体验版

**改完域名必须重新上传代码**，旧包仍走旧配置。

HBuilderX → **发行 → 小程序-微信** → 上传 → 在微信后台设为体验版。

> ⚠️ 注意是「**发行**」不是「运行」。用「运行」打包出来的代码，体验版用不了。

### 3. 手机上清缓存

长按删除小程序 → 重新扫码进入。
（微信会缓存旧版本，不清可能还是老样子。）

## 六、域名配置的硬性要求（容易踩的坑）

| 要求 | 说明 |
|---|---|
| **必须 HTTPS** | `http://` 一律拒绝 |
| **必须已备案** | 域名要有 ICP 备案 |
| **不能用 IP** | `192.168.13.30` 这种永远不可能配进白名单 |
| **端口必须一致** | 配了 `https://a.com:8080` 就只能请求 8080；不配端口的话，URL 也不能带端口 |
| **子域名不继承** | `api.a.com` 和 `a.com` 是两条，要分别加 |

---

## 七、服务端是好的（我实测过）

排查过程中我直接压测了上传接口，排除服务端嫌疑：

| 文件大小 | 线上 `y.bobay.top` |
|---|---|
| 1 MB | ✅ 上传成功 |
| 3 MB | ✅ 上传成功 |
| 6 MB | ❌ 提示「图片不能超过 5MB」（**我们自己的限制**，属正常） |

**结论：线上服务器的上传功能完全正常**，图片能存进去、能公网访问。问题 100% 在客户端侧的域名校验。

---

## 八、顺带发现的另一个坑（本地开发）

排查时发现**本地 PHP 的上传上限只有 2M**：

```
upload_max_filesize = 2M      ← 默认值
post_max_size       = 8M
```

**后果**：本地开发时，任何超过 2MB 的图片会被 **PHP 在进入我们代码之前就丢弃**，
表现是提示「请选择要上传的图片」（因为 `$_FILES` 是空的），**而不是「图片超过 5MB」**。

实测对比：

| 大小 | 线上 | 本地 |
|---|---|---|
| 1MB | ✅ | ✅ |
| 3MB | ✅ | ❌ 被 PHP 丢弃 |
| 6MB | ❌（5MB 限制） | ❌ 被 PHP 丢弃 |

**建议**：把本地的 `php.ini` 改成和线上一致，否则本地测不出大图问题：

```ini
upload_max_filesize = 10M
post_max_size       = 12M
```

改完重启 PHP 服务。文件位置：`php --ini` 可以看到 `Loaded Configuration File`。

> 线上服务器的大于 6M，不用改。但如果你也部署了别的地方，值得确认一遍。

## 十、我的判断依据（供你复核）

1. **症状定位**：只有上传挂、其他功能正常 → 指向 `uploadFile` 独有的东西（它的域名白名单）
2. **环境差异**：只有体验版挂 → 指向「体验版才强制校验域名」这条规则
3. **排除代码**：「压缩中」三个字全项目搜不到，是我们控制不了的客户端提示
4. **排除服务端**：直接压测线上上传接口，1MB/3MB 均成功
5. **官方文档**：`uploadFile 合法域名` 与 `request 合法域名` 确为独立列表，且必须 HTTPS + 备案
